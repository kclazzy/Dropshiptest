# Журнал разработки (Rust + Tauri v2)

Прежняя реализация на C++20 удалена по решению владельца (безопасность памяти); она остаётся в истории git (`5af626f`).

## Шаг 1 — основа

**Сделано:** Cargo workspace (`src-tauri`), миграция со схемой из ТЗ, пул SQLite (WAL, `synchronous=NORMAL`, `foreign_keys`, `busy_timeout=5s`), модели, очередь задач (`enqueue_task`, `dequeue_next_task` одним `UPDATE … RETURNING`, `complete_task`, `fail_task`, `defer_task`), `PricingEngine`, команда Tauri `price_breakdown` и React-калькулятор.

**Проверено:** 29 тестов (`cargo test`), включая перебор ~2000 комбинаций правил/цен с проверкой инвариантов и гонку 8 воркеров за 200 задач (15 запусков подряд без сбоев); `cargo clippy --all-targets` без замечаний; `npm run build` фронтенда; компиляция приложения Tauri.

**Решения и отклонения от ТЗ**
1. **Прибыль — цель, а не побочный результат.** Цена — наименьшая, при которой фактическая чистая прибыль (комиссии округляются вверх по отдельности) не ниже `max(маржа + фикс. наценка, min_profit_minor)`. Это то же, что формула ТЗ, но без потери 1–2 копеек из-за округления. `raised_to_min_profit` показывает, что цена поднята ради минимальной прибыли.
2. **`min_price`** — безубыточная цена (прибыль ≥ 0), «без ухода в минус». `old_price = retail / (1 − скидка)`.
3. **`rounding_minor`** — шаг округления вверх (1000 = до 10 ₽); 0 — без округления. Психологические окончания (…99) пока не поддерживаются.
4. `acquiring_and_tax_percent` в схеме один (эквайринг + налог вместе), `F_packaging` передаётся во входных данных, в таблице его нет.
5. **`rquest` не используется:** на crates.io это пустая заглушка `0.0.0` (проект переименован в `wreq`, версия 6.0 пока release candidate, тянет BoringSSL). Решение по клиенту с подменой TLS-отпечатка — на шаге мониторинга, после проверки сборки `wreq`.
6. Секреты (`encrypted_credentials`, `proxy_url`) помечены `#[serde(skip)]` и не попадают в интерфейс.
7. Ошибки: `AppError::to_user_friendly_ru()`; в команды Tauri уходит только русский текст.

**Не сделано в шаге 1 (по плану):** адаптеры площадок, ИИ, мост и расширение, мониторинг, заказы, трей, мастер запуска, шифрование ключей.

**Пожелание владельца (получено во время шага 1):** кроме Ollama добавить **облачные ИИ-решения с инструкциями** → шаг 2: интерфейс `ContentGenerator` с реализациями Ollama и облачных провайдеров (OpenAI-совместимые, Anthropic, Gemini, Yandex и др.), ключи только в зашифрованном хранилище, раздел инструкций «как получить ключ».
