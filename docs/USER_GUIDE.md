# Dropship — инструкция пользователя

Что делает программа: вы открываете страницу товара у поставщика (в любом интернет-магазине), нажимаете кнопку в расширении — товар попадает в локальную базу, а ИИ готовит для него название, описание и теги. История цен и ваши правки хранятся отдельно от данных поставщика и ничего не теряют.

**Состав:** ядро (программа `dropship_core_app`) + расширение для Chrome/Edge/Brave + ИИ (локальная Ollama или любое облако).

> **Что уже работает, а что ещё нет.** Работает: импорт товара с любой страницы, база с историей и журналом правок, генерация карточки ИИ (локально и в облаке), **автоматический мониторинг цен и остатков с расчётом розничной цены**, обновление в один клик, запуск в облаке. **Отправка цен и остатков на Ozon и Avito** уже написана, но **не проверена на живых аккаунтах** (см. раздел 8). **Ещё не готово:** создание новых карточек на площадках (карточку нужно создать в кабинете самому), заказы и трек-номера, автовыкуп и окно с таблицей товаров. Пока смотреть и править данные можно через `sqlite3` (раздел 6). Подробности — в таблице «План» в README.

## 1. Установка (Linux/macOS)

Нужны: `git`, `cmake` 3.25+, компилятор C++20 (GCC 13+/Clang 16+), библиотеки SQLite3, OpenSSL, libcurl, Boost (заголовки), nlohmann-json, и Node.js 20+ для расширения. Для Ubuntu:

```bash
sudo apt install git g++ cmake ninja-build libsqlite3-dev libssl-dev libcurl4-openssl-dev libboost-dev nlohmann-json3-dev nodejs npm
git clone https://github.com/kclazzy/Dropshiptest.git
cd Dropshiptest
scripts/build.sh
```

Windows: ядро собирается через vcpkg (`core-cpp/vcpkg.json`) и CMake, запуск — `scripts\run.cmd`. Сборка под Windows пока **не проверялась** — если что-то не получится, напишите, что показала ошибка.

## 2. Запуск ядра

```bash
scripts/run.sh
```

В окне появится строка «Dropship core … is running». Данные хранятся в `~/.dropship` (или в папке из `--data-dir`/`DROPSHIP_DATA_DIR`):

| Файл | Что это |
|---|---|
| `dropship.db` | вся база: товары, варианты, история цен, журнал правок |
| `bridge.token` | пароль для расширения (64 символа). Никому не показывайте |
| `settings.json` | настройки ИИ и обновлений |

Остановить — `Ctrl+C`. Запускайте именно через `scripts/run.sh`: только так работает кнопка обновления.

## 3. Установка расширения

1. Откройте `chrome://extensions`, включите «Режим разработчика».
2. «Загрузить распакованное расширение» → папка `extension-mv3/dist`.
3. Нажмите значок Dropship → «Настройки» → вставьте содержимое файла `bridge.token` → «Сохранить».
4. Вверху должно появиться «Связь с ядром установлена».

Расширение просит минимум прав: оно ничего не запускает на сайтах само — только когда вы нажимаете кнопку.

## 4. Добавление товара (Ozon, Avito и любые другие сайты)

1. Откройте страницу **конкретного товара** у поставщика.
2. Нажмите значок Dropship → «Добавить товар с этой страницы».
3. Появится «Добавлено: …». Повторное добавление того же товара не создаёт дубликат (ссылки с `utm_` и т. п. считаются одной ссылкой).

Расширение читает стандартную разметку магазинов (schema.org/JSON-LD, Open Graph). Если сайт её не отдаёт, вы увидите «Не удалось найти цену» — тогда товар пока добавить нельзя.

Товары попадают в «Мой каталог» — локальный магазин, который создаётся при первом запуске. Когда появятся адаптеры Ozon/Avito, товары можно будет привязывать к вашим магазинам на этих площадках; поле «Номер магазина» в настройках расширения нужно только тогда.

**Сессия поставщика.** Кнопка «Передать сессию сайта в ядро» отправляет куки текущего сайта в память ядра (на диск они не пишутся) — нужно для будущего мониторинга закрытых страниц. Браузер спросит разрешение отдельно для этого сайта.

## 5. ИИ: описание, заголовок, теги

По умолчанию — локальная Ollama (бесплатно, данные не уходят с компьютера):

```bash
ollama pull qwen3.5:9b-q4_K_M      # модель по умолчанию; если такой нет — выберите другую и впишите в settings.json
```

Облачные провайдеры (OpenAI, Claude, OpenRouter, Groq и др.) подключаются в `settings.json`; пошаговая инструкция — в [CLOUD.md](CLOUD.md). После правки `settings.json` перезапустите ядро.

Результат ИИ не затирает ваши правки: приоритет «ваш текст → текст ИИ → оригинал поставщика».

## 6. Просмотр товаров, истории и правок

Пока без окна: нужна утилита `sqlite3` (`sudo apt install sqlite3`).

```bash
sqlite3 -header -column ~/.dropship/dropship.db \
  "SELECT id, title, ai_status, variant_count, total_stock, supplier_url FROM v_product_overview;"
```

- `v_product_overview` — список для просмотра: итоговое название (ваше → ИИ → оригинал), статус ИИ, число вариантов, остаток, `min_retail_price_cents`/`max_retail_price_cents` (розничная цена в копейках; `0` — ещё не рассчитана: расчёт цен появится вместе с мониторингом).
- `price_history` — каждое реальное изменение цены/остатка варианта с датой.
- `audit_log` — кто и что поменял в карточке.
- Ваши правки: `UPDATE products SET title_override = 'Новое название' WHERE id = 1;` — оригинал поставщика и текст ИИ остаются, правка попадает в `audit_log`.

`ai_status`: `PENDING` — в очереди, `PROCESSING` — генерируется, `READY` — готово, `ERROR` — не удалось (причина в `task_queue.error_log`).

## 7. Мониторинг цен и остатков

Ядро само проверяет страницы поставщиков: по умолчанию каждые 30 минут на товар (`products.check_interval_sec`). Если цена или остаток изменились, новое состояние сохраняется, в `price_history` появляется строка, пересчитывается розничная цена. Если ничего не изменилось — в базу ничего не пишется.

**Розничная цена считается по правилам магазина** (таблица `pricing_rules`): диапазон закупочной цены, наценка, комиссия площадки, округление до `.99`, порог остатка. Пока правил нет, розничная цена не меняется (в `v_product_overview` она будет `0` или прежней). Пример: наценка 30 % для любых цен, остаток меньше 5 шт. считается «нет в наличии»:

```bash
sqlite3 ~/.dropship/dropship.db "INSERT INTO pricing_rules(store_id, price_from_cents, price_to_cents, margin_percent, fixed_markup_cents, marketplace_fee_percent, rounding_cents, min_stock_threshold, min_profit_cents) VALUES (1, 0, 9223372036854775807, 30, 0, 10, 99, 5, 200);"
```

(`store_id` смотрите в таблице `stores`; цены — в копейках; диапазоны не должны пересекаться; `price_to_cents` — до какой цены, не включая.)

**Защита остатков.** Если у поставщика осталось меньше порога или вариант исчез со страницы, вариант получает `is_in_stock = 0` — именно так он будет передан на витрину (сама передача появится вместе с адаптерами).

**Статусы товара (`monitor_status`):**

| Статус | Что значит | Что делать |
|---|---|---|
| `ACTIVE` | проверяется по расписанию | — |
| `CAPTCHA_BLOCKED` | поставщик ответил 403/429 (капча или бан) | откройте сайт в браузере, пройдите проверку и нажмите «Передать сессию сайта в ядро» — карточки домена вернутся в мониторинг сами |
| `PAUSED` | страница пропала (404/410) — остаток обнулён; либо вы поставили паузу | `UPDATE products SET monitor_status='ACTIVE' WHERE id=…` |
| `ERROR` | несколько проверок подряд не удались (страница без цены, сбои сети) | исправьте причину (см. `task_queue.error_log`) и верните `ACTIVE` |

**Прокси (необязательно).** Если поставщик блокирует частые запросы, добавьте прокси — ядро будет ротировать их и давать «отдохнуть» сбойным (HTTP/HTTPS/SOCKS5):

```bash
sqlite3 ~/.dropship/dropship.db "INSERT INTO proxies(proxy_url) VALUES ('socks5://user:pass@1.2.3.4:1080');"
```

Если прокси добавлены, но все сейчас на отдыхе, ядро ждёт — напрямую (с вашего адреса) оно в этом случае не ходит. Прокси, подряд подведший 5 раз, отключается (`is_active = 0`).

**Настройки** в `settings.json`: `"monitor": {"workers": 4, "schedule_seconds": 15}` — число параллельных проверок (0 — мониторинг выключен) и как часто искать карточки, которым пора проверяться.

Мониторинг читает цену из стандартной разметки (schema.org / meta), как и импорт. Страницы, которые рисуются только браузерным JavaScript, пока не поддерживаются (позже — через расширение).

## 8. Подключение Ozon и Avito: цены и остатки на витрину

> **Важно.** Адаптеры отправляют на площадку **остатки и цены уже существующих карточек**. Создавать новые карточки (категории, обязательные атрибуты) они не умеют — создайте карточку в кабинете площадки сами. Адреса и форматы запросов я сверял по вторичным источникам и по памяти: официальную документацию Avito открыть не удалось, форма запроса цен Ozon не подтверждена. Поэтому **сначала проверьте на одном товаре**, и только потом привязывайте весь каталог.

**Шаг 1. Ключи.** Они вводятся командой через stdin (не попадают в историю терминала) и хранятся в базе только зашифрованными (AES-256-GCM, ключ — файл `~/.dropship/secret.key`; сделайте его резервную копию отдельно от базы!).

Ozon (нужны Client-Id, Api-Key из кабинета продавца и номер FBS-склада):

```bash
echo '{"client_id":"123456","api_key":"ваш-ключ","warehouse_id":1020001234567}' | scripts/dropship.sh store-add --name "Мой Ozon" --platform ozon
```

Avito (client_id и client_secret приложения из developers.avito.ru; API остатков доступен не на всех тарифах):

```bash
echo '{"client_id":"…","client_secret":"…"}' | scripts/dropship.sh store-add --name "Мой Avito" --platform avito
```

Список магазинов и последние ошибки отправки: `scripts/dropship.sh store-list`.

**Шаг 2. Куда попадают товары.** При импорте без указания магазина товар попадает в первый активный магазин. Если вы добавили Ozon/Avito в самом начале, это он. Номер магазина можно задать в настройках расширения.

**Шаг 3. Привязка.** Каждый вариант товара нужно связать с карточкой на площадке: `offer_id` для Ozon, числовой `item_id` объявления для Avito.

```bash
scripts/dropship.sh variants                      # номера вариантов и их привязки
scripts/dropship.sh link --variant 12 --external OFFER-123
scripts/dropship.sh link --variant 12 --external -   # отвязать
```

**Шаг 4. Правила цен** (раздел 7). Пока для закупочной цены нет правила, цена на витрину **не отправляется** (уходит только остаток).

**Как идёт отправка.** После привязки и при каждом изменении цены/остатка ядро само отправляет новое состояние: цены в целых рублях **с округлением вверх**, остаток 0, если он ниже порога правила. То, что уже отправлено, повторно не шлётся. Лимиты запросов соблюдаются (Ozon — около 80 в минуту). Если площадка отклонила вариант (например, нет такого `offer_id`), причина видна в `store-list`, а повторные попытки не делаются, пока вы не исправите привязку или не изменится цена. Неверный ключ — отправка останавливается, ошибка видна в `store-list`.

## 9. Обновление в один клик

1. Запускайте ядро через `scripts/run.sh` (Windows — `scripts\run.cmd`).
2. Нажмите значок Dropship. Если вышла новая версия, появится жёлтый блок «Доступна версия …» → **«Обновить в один клик»**.
3. Ядро завершится, скрипт сам скачает изменения (`git pull`), пересоберёт ядро и расширение и запустит ядро заново. Расширение перезагрузится само примерно через минуту. База и настройки не затрагиваются.

Новая версия «выходит» тогда, когда в репозитории публикуется релиз с тегом `vX.Y.Z` (для владельца репозитория: `gh release create v0.2.0 --generate-notes`, версия в `core-cpp/CMakeLists.txt` должна совпадать). Обновиться вручную можно всегда: `scripts/update.sh`.

Если обновление не удалось, скрипт запускает прежнюю версию — потери данных нет. Обновление рассчитано на установку из `git clone`.

## 10. Если что-то не работает

| Симптом | Что делать |
|---|---|
| «Нет связи с ядром» | Запущено ли `scripts/run.sh`? Не занят ли порт 8765 (`--port`)? |
| «unauthorized» / не пускает | Токен в настройках расширения должен совпадать с `bridge.token`. Удалите файл и перезапустите ядро — создастся новый, вставьте его заново |
| «Не удалось найти цену» | Откройте страницу конкретного товара, а не список/поиск |
| `ai_status = ERROR` | `sqlite3 ~/.dropship/dropship.db "SELECT error_log FROM task_queue WHERE status='FAILED'"` — частые причины: Ollama не запущена, нет ключа API, неверное имя модели |
| Цена/остаток не появились на Ozon/Avito | `scripts/dropship.sh store-list` (ошибка), `variants` (привязан ли вариант), есть ли правило цены, не отключён ли магазин |
| Цена не обновляется | Статус товара (`monitor_status`), `task_queue.error_log`; страница должна отдавать цену в разметке без JavaScript |
| ИИ «отключён» в логе ядра | Ошибка в `settings.json` — строка лога скажет, в каком поле |
| Кнопки «Обновить» нет | Ядро запущено не через `run.sh`, или новых релизов нет |
