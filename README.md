# Dropshiptest

Локальная гибридная система автоматизации дропшиппинга: **C++20 ядро** + **расширение браузера (Manifest V3)** + **локальная LLM (Ollama)**. Работает на ПК пользователя, без облачных посредников. Модель данных рассчитана на несколько площадок, включая Ozon, Avito, Wildberries, Яндекс Маркет, Shopify, WooCommerce и eBay.

## Структура

```
core-cpp/          C++20 ядро (CMake, vcpkg)
  src/core/        Domain.hpp (Platform, TaskType, Cents), Expected.hpp
  src/pricing/     PricingEngine: цена в int64 копейках, диапазонные правила, мин. прибыль
  src/db/          DatabaseManager: SQLite WAL, миграции, история, очередь задач
  src/ai/          ИИ: Ollama (Structured Outputs) и облако (OpenAI-совместимые, Anthropic), очередь AI_REWRITE
  src/bridge/      WebSocket-мост для расширения (JSON-RPC 2.0, токен, только loopback)
  src/importer/    импорт товара из расширения, дедупликация по ссылке
  src/monitor/     мониторинг: разбор страницы, планировщик, воркеры PRICE_SYNC, пул прокси, лимиты доменов
  src/store/       витрины: IStoreAdapter, Ozon, Avito, лимитер, сейф ключей, отправка цен/остатков
  src/update/      проверка обновлений (релизы GitHub)
  src/app/         dropship_core_app — запускаемое ядро
  tests/           юнит-тесты (267)
extension-mv3/     расширение браузера (TypeScript, esbuild, vitest): импорт со страницы, куки, обновление
scripts/           build.sh, run.sh/run.cmd (запуск с обновлением), update.sh/update.cmd
docs/              USER_GUIDE.md, CLOUD.md, журнал разработки, глоссарий
Dockerfile, docker-compose.yml   запуск ядра на сервере (не проверено в среде разработки)
```

См. [docs/USER_GUIDE.md](docs/USER_GUIDE.md) (установка, расширение, импорт, обновление в один клик) и [docs/CLOUD.md](docs/CLOUD.md) (облачные ИИ-провайдеры, запуск на VPS).

## Сборка и тесты (ядро)

```bash
cd core-cpp
cmake -S . -B build -G Ninja
cmake --build build
ctest --test-dir build --output-on-failure
```

Нужны компилятор C++20 (GCC 13+, Clang 16+, MSVC 19.34+), CMake 3.25+ и SQLite3 (системный или через vcpkg: `-DCMAKE_TOOLCHAIN_FILE=<vcpkg>/scripts/buildsystems/vcpkg.cmake`).

## Что уже есть (Шаг 1)

- **Деньги без float:** суммы в минимальных единицах, проценты в базисных пунктах; переполнение — ошибка, а не UB.
- **PricingEngine:** `P = (C + S + F) × (1 + маржа) / (1 − комиссия)`, диапазоны по закупочной цене, психологическое округление (`.99`, `.90`, …), флаг минимальной прибыли, защита остатков.
- **База данных:** WAL, один писатель + пул читателей, параметризованные запросы, идемпотентные миграции.
- **Редактирование и история для пользователя:** правки названия/описания/заметок хранятся отдельно от данных поставщика; `price_history` (цены и остатки) и `audit_log` (правки карточек, статусы заказов) заполняются триггерами; представление `v_product_overview` отдаёт список товаров для GUI.
- **Очередь задач:** атомарный захват (`UPDATE … RETURNING`), приоритеты, повторы с задержкой, возврат «брошенных» задач.
- **Валюта магазина** (`stores.currency`) — для площадок в рублях.

## Что есть (Шаг 2)

- **Расширение → ядро:** кнопка в popup читает JSON-LD/Open Graph со страницы (скрипт внедряется только по клику) и отправляет товар в ядро; куки поставщика — по отдельному разрешению.
- **Мост:** `ws://127.0.0.1:8765/ws`, первый пакет — AUTH с токеном из `bridge.token`, проверка Origin (веб-страницы отклоняются), один клиент, лимит размера.
- **ИИ:** `IContentGenerator` — Ollama или облако (openai, anthropic, openrouter, groq, together, mistral, deepseek, gemini, yandex, custom); ключи только из окружения/файла-секрета.
- **Воркер ИИ:** задачи `AI_REWRITE` из очереди, повторы при временных ошибках, окончательный `ERROR` при неверном ключе; правки пользователя не затираются.
- **Обновление в один клик:** `UPDATE_CHECK` / `UPDATE_APPLY`, установку делает `scripts/run.sh` (код выхода 75).

## Что есть (Шаг 3)

- **Планировщик:** карточки, у которых наступил срок проверки, ставятся в очередь `PRICE_SYNC` (без дублей).
- **Воркеры:** скачивают страницу поставщика с куками и User-Agent из браузера, через пул прокси (ротация, растущий кулдаун, отключение), с лимитом на домен; редиректы — вручную, куки только на домен поставщика.
- **Исходы:** цена/остаток изменились → пересчёт розницы по `pricing_rules` и запись в `price_history`; без изменений → запись пропускается (хэш состояния); 403/429 → `CAPTCHA_BLOCKED` до новой сессии из расширения; 404/410 → остаток 0 и пауза; сбои → повтор, затем `ERROR`.
- **Защита остатков:** ниже порога правила → вариант `is_in_stock = 0`.

## Что есть (Шаг 4)

- **IStoreAdapter** + `TokenBucketRateLimiter` на каждый магазин; Ozon и Avito: остатки и цены существующих карточек.
- **Ключи магазинов** хранятся в БД зашифрованными (AES-256-GCM), ключ — отдельный файл `secret.key`; ввод через stdin (`store-add`).
- **Синхронизация:** задачи `STORE_PUBLISH` для изменений, ещё не отправленных; хэш отправленного состояния (повтор не шлётся), отклонённое не долбится, лимиты → отложить без расхода попытки, неверный ключ → остановка с понятной ошибкой в `store-list`.
- ⚠ Адаптеры **не проверены на живых аккаунтах** (см. docs/USER_GUIDE.md, раздел 8).

## Что есть (Шаг 5)

- **Заказы:** приём идемпотентный (по номеру заказа), проверка остатка, правила цены и минимальной прибыли по текущим ценам поставщика; сомнительное — в `MANUAL_REVIEW` с причиной.
- **Выкуп через расширение (ассистированный режим):** ядро шлёт `EXECUTE_AUTO_ORDER`, расширение открывает страницу поставщика, человек оформляет и платит; результат и трек возвращаются в ядро. Покупка **никогда не повторяется автоматически**, если исход неизвестен.
- **Трек-номера:** `SHIPPED` + задача `TRACKING_SYNC`; если площадка не принимает трек — понятная пометка «введите вручную».
- **CLI:** `order-add`, `orders`, `order-done`, `order-track`, `order-retry`.
- ⚠ Автозаполнение/автооплата не реализованы; приём заказов и трек Ozon/Avito по API не реализованы (внесите заказ командой).
